# Project-native workspace migration

`projects[]` is the canonical registry for repositories, Power sources, products, and runtime targets.

## Runtime targets

A project is a runtime target when its `roles` contains `product` or `runtime-target`.

Target-local configuration belongs under the project entry:

```yaml
projects:
  - id: example
    path: projects/example
    source: owner/example
    roles: [product]
    powers:
      enabled: [gwc, ua, task-me, bmad]
    orchestration:
      primary: gwc
      workers: [task-me, bmad, ua]
```

The top-level `systems[]` registry is invalid and must not be generated by installers, templates, validators, doctor commands, or distribution tooling.

## Distribution boundary

Power packages, inbox, cache, history, bindings, and host adapters remain workspace-owned. Runtime data remains project-owned.

Existing binding directory names remain stable because registered project paths resolve to the same project IDs previously used as system IDs. No package reinstall or binding relocation is required.

## Compatibility

- `powers[]` references Power source projects using `project` and must not duplicate `path` or `source`.
- `data_ownership.policy` is `project-owned`.
- CLI surfaces may retain `dw system ...` as a deprecated read-only alias, but resolution must use project runtime targets.
- Offline and full-distribution templates must emit no `systems` key.
